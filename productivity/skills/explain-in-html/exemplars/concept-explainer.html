Bloom filters, in one bit array

You want to know whether you've seen a key before, but you have a billion keys and not enough memory to hold them. A Bloom filter answers that question in a few bits per key — at the cost of sometimes saying "yes" when the answer is no. It never says "no" when the answer is yes, and that asymmetry is the whole reason it's useful.

The trick: don't store the key, store where it lands

Keep a bit array of m bits, all zero. To add a key, run it through k hash functions, each producing an index, and set those bits to 1. To test a key, hash it the same way and look: if any of its bits is 0 it was definitely never added. If all are 1 it was probably added — or other keys happened to set exactly those bits between them, which is a false positive.

Clay cells are set. Add keys and watch the array saturate — once most bits are 1, "probably yes" stops meaning anything. The measured rate is sampled over 500 keys that were never added.

Why it only errs one way

Bits are never cleared. So every key that was added still has all of its bits set, and a lookup for it cannot fail — there are no false negatives, ever. The reverse isn't protected: a key that was never added can find its bits already set by unrelated neighbours. The more keys you add, the more of the array is 1, and the likelier that coincidence becomes.

That gives the standard estimate for the false-positive rate after n insertions: (1 − e−kn/m)k. It also explains the shape of the tuning problem — more hashes set more bits per key, so k helps until it starts filling the array on its own.

Where you'll meet it

Anywhere a cheap "definitely not" saves an expensive lookup. Storage engines check one before touching an on-disk table; CDNs use one to avoid caching single-hit objects; crawlers use one to skip URLs already visited. The pattern is always the same shape — the filter sits in front of something slow, and its false positives cost you only a wasted check, never a wrong answer.

Glossary
Bit array
The m bits that are the entire filter. No keys are stored, only the marks they leave.
Hash functions
The k independent functions mapping a key to k positions in the array.
False positive
A lookup reporting "probably present" for a key never added, because other keys set its bits.
Saturation
The fraction of bits set to 1. As it approaches 1, every lookup returns "probably present".
Union
Two filters of the same size and hashes OR together into a filter of both their key sets.
